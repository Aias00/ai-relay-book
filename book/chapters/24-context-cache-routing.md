# 第 24 章：上下文缓存与语义路由的组合

语义路由选择合适的模型，缓存亲和选择更可能复用上下文的执行资源。二者可以组合，但应先保证能力与质量，再优化缓存、费用和延迟。

## 24.1 四种缓存不要混淆

| 类型 | 位置 | 路由要求 |
| --- | --- | --- |
| 前缀或 Prompt Cache | 上游模型服务 | 尽量保持有效缓存作用域 |
| 显式上下文缓存 | 上游缓存 ID 对应服务 | 绑定能访问该 ID 的资源 |
| 会话历史 | 应用或网关 | 共享状态或明确会话归属 |
| 响应缓存 | 网关 | 缓存键覆盖权限、模型、参数和输入语义 |

前缀缓存通常减少重复输入计算、费用或等待，不一定减少传输的 token 数，也不一定降低上下文占用。真正缩短输入需要裁剪、检索或摘要；这些操作可能改变前缀。

不同模型一般不能直接共享模型内部的前缀计算结果。同名模型的不同账号、项目、部署是否共享缓存，也取决于供应商约定。本章不假设任何供应商当前承诺特定命中率、隔离范围或价格。

## 24.2 入口负载与上游亲和是两层

```text
第一轮 → 数据面 A → 上游资源 X
第二轮 → 数据面 B → 上游资源 X
```

只要上下文满足条件且资源处于可复用缓存范围，数据面换节点未必影响命中。反过来，两次都到 A 却使用不同上游资源，也未必复用缓存。

因此普通 SSE 不必为了上游缓存绑定数据面实例。多个数据面可共享“租户、会话、模型 → 优先缓存作用域”的短期映射；一致性哈希也可以生成候选，但不能证明上游实际有缓存。

优先资源健康、权限有效、容量足够时继续使用；过载或失败时回退。软亲和只表达偏好，不覆盖停用、安全和能力限制，也不保证缓存未被淘汰。

## 24.3 显式缓存引用需要强约束

如果请求只提供缓存 ID，没有原始内容，切换到其他账号或供应商可能无法执行。应记录 ID 的租户归属、供应商、作用域、有效期、兼容模型和重建材料。

有授权材料时可以重建；无法重建则返回明确错误，不能忽略缓存 ID 后当作空历史继续生成。缓存引用也不能成为绕过跨租户权限的方式。

## 24.4 稳定前缀与阶段性压缩

可将上下文组织为稳定系统指令、稳定工具定义、固定背景材料、追加历史和本轮输入。不要每轮在最前面注入随机标识、路由解释或变化时间。协议转换与工具顺序应保持稳定，缓存控制标记不能无意丢失。

先裁剪明确无关内容，再构造可复用前缀。历史以追加为主，达到阈值或任务边界时再生成新摘要。每轮重写摘要可能持续破坏缓存；分阶段压缩可以在一段时间内复用相同摘要。

摘要有成本和信息损失，不能为了放进小模型就静默删除关键历史。需要切换模型时，应具备供应商之外的必要会话材料，不能只依赖不可移植的缓存引用。

## 24.5 语义模型选择与缓存成本

先根据模态、工具、结构化输出、上下文、权限与质量筛选合格模型，然后估算各模型的费用与延迟。

```text
预计输入费用
  = 缓存读取数量 × 读取单价
  + 未缓存输入数量 × 普通单价
  + 适用的缓存写入费用

预计总费用
  = 输入费用 + 输出费用 + 路由器费用
  + 必要的摘要或重建费用
```

不同供应商计量类别可能重叠，公式中的类别需要先归一化，不能重复计费。命中不确定时分别估算命中与未命中场景，再按经过校验的概率计算期望值。

代码分析后的一句“总结一下”虽然简单，但切到小模型可能重新处理全部长历史。保留已有缓存的较强模型，有时反而更便宜。应比较整个任务成本，不是单次模型单价。

## 24.6 控制切换和评估收益

首轮按任务选择模型，后续任务相同且能力满足时优先保持。明确的新能力需求、不可用或显著收益才触发切换；设置切换门槛，避免小幅评分变化导致来回跳转。

路由器优先读取接口特征、最新输入和简短会话状态，不能为了省钱每次先让大模型读取完整历史。分类开销必须纳入总成本。

验收同时看质量、任务总成本、首内容延迟、切换率、实际缓存用量与重试。缓存命中率高不代表整体成本低，预计命中也不能直接作为最终收费依据。
