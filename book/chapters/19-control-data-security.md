# 第 19 章：控制面与数据面及凭证安全

控制面管理用户、渠道、模型和策略生命周期；数据面执行鉴权、准入、路由与转发。账务模块负责账户与结算。三者可以先共进程部署，职责明确后再选择独立扩缩容。

## 19.1 拆进程与拆安全边界

只让管理 API 和转发 API 使用不同端口或进程，继续共享数据库管理员权限、完整账号池与密钥，可以改善部署和扩容，但没有建立清晰的权限隔离。

真正拆分需要回答：数据面能读取哪些资源，配置如何发布，实时状态归谁管理，停用如何传播，控制面断联能服务多久，以及在途流和后台任务如何结束。原来的内部函数调用需要变成明确协议，而不是逐个改成远程查询。

已有工程的具体预算与请求路径见第 2、8、9、10 章。不能仅凭 service、repository 或 open-sse 目录认定已经具备独立控制面。后续本地源码观察显示，三个项目主调用路径都需要接触上游凭证；本章的隔离方案是目标架构，不是已有项目功能声明。

## 19.2 两种 Key 不互相转换

```text
客户端平台 Key → 网关鉴权 → 用户与权限
                              ↓
                         路由选择账号
                              ↓
上游凭证 → 构造供应商认证请求 → 上游
```

平台 Key 决定谁可以访问哪些服务，上游 Key 决定以哪个供应商账号调用。通常是多对多映射，没有算法把客户端 Key 转成上游 Key。网关应过滤客户端认证信息，再按所选账号设置上游认证头。

## 19.3 客户端凭证不必作为明文配置下发

对于高随机性平台 Key，控制面可以保存公开标识、秘密部分的校验摘要、权限和状态，数据面得到验证材料。客户端实际调用仍会携带原文，因此接收请求的组件仍处于敏感信任边界，日志、转储和错误报告必须排除可用凭证。

也可以由认证入口签发短期内部令牌，使执行节点只看到用户与权限。令牌需要约束受众、有效期和可访问资源，撤销时效也要明确。高熵 API Key 的摘要验证不能直接套用于低熵用户密码。

在本地源码复核的路径中，new-api 与 sub2api 对缓存索引分别使用 HMAC 或 SHA-256，并不意味着数据库只存摘要；其平台 Key 查询仍使用传入值匹配。9router 的平台 Key 也由本地表保存和匹配。这些应用层观察不评价部署侧磁盘或数据库加密。新增证据见[来源附录](91-sources.md)。

## 19.4 上游密钥的运行时边界

数据面直接发送 Bearer 凭证时，通常必须接触明文。加密下发、KMS 和加密存储可以保护传输与静态数据，却无法防止具备解密能力的失陷进程读取正在使用的密钥。

可先缩小影响范围：每个节点仅获授权账号的凭证，使用实例身份取密钥，避免落入日志和镜像，支持轮换与撤销。OAuth 的刷新凭证可以留在受控服务，执行节点只获得短期 Access Token。对供应商支持的签名认证，可以使用独立签名服务。

若要求执行节点不接触上游 Key，需要独立出口代理：

```text
客户端 → 认证入口 → 执行节点 → 受控出口 → 供应商
                                  ↑
                             凭证服务
```

出口不能成为可任意消费的代理。它必须验证调用身份、账号与模型权限、目标域名和路径、重定向策略、有效期与额度，并阻止调用方覆盖认证头。拿不到密钥但能无限借代理调用，仍然有同等消费风险。

## 19.5 选择隔离程度

按需取凭证直接调用，链路短但执行节点属于密钥信任边界；独立出口缩小密钥暴露范围，却增加转发、连接容量和高可用责任。不要把后者当作拆控制面必需的第一步。

控制面和数据面的通信应使用经过验证的实例身份与授权，传输加密并不等于允许所有实例获取全量配置。配置订阅范围、凭证访问范围和运行事件访问范围都需要独立限制。
