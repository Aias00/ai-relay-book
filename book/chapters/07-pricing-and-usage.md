# 第 7 章：先统一计量，再计算价格

同样叫 input_tokens，不同上游可能采用不同统计口径。有的输入总量包含缓存，有的将缓存独立报告。如果直接把所有字段乘单价相加，就可能重复收取缓存费用。计价的第一步是确认用量集合之间的关系。

## 7.1 用量、单价、倍率和额度

用量描述发生了多少：Token、图片张数、视频秒数或供应商资源点。单价描述每个单位多少钱。倍率表达用户分组或特定请求条件带来的调整。额度则是系统内部的记账单位。

new-api 默认 `QuotaPerUnit = 500000`，即一美元转换为五十万 Quota。sub2api 的在途预留使用美元金额。9router 的 usage 历史保存 Token 与按定价计算的 cost。三者的数字不能脱离单位比较。[N][S][R](91-sources.md)

## 7.2 new-api 的表达式口径

表达式 `tier("base", p * 2 + c * 8 + cr * 0.2)` 中的系数表示美元/百万 Token。假设上游返回输入总量 10000，其中缓存读取 8000，输出 1000，且分组倍率为 1：

```text
普通输入：2000 × 2 / 1000000 = $0.004
缓存读取：8000 × 0.2 / 1000000 = $0.0016
输出：    1000 × 8 / 1000000 = $0.008
总费用：$0.0136 = 6800 Quota
```

系统根据表达式引用的变量拆分输入；表达式没有引用 `cr` 时，缓存读取通常并入基础输入计价。长效缓存写入还有独立归一化规则，不能把缓存读取示例直接套到所有缓存类别。阶梯条件使用完整上下文 `len`，不能用扣除缓存后的 `p` 判断长上下文档位。

这些系数仅为演示。管理员覆盖、分组倍率、定价模型名和工具附加费都会改变实际结果。源码入口是 `relay/helper/price.go`、`service/tiered_settle.go` 与 `pkg/billingexpr/expr.md`。

## 7.3 按次与任务不是 Token 公式的别名

表达式 `tier("request", fixed(0.01))` 表示请求基础费用一美分，不是每个 SSE chunk 收费。图片可以按张或按图片 Token 计价；按 Token 算出的总量不应再乘一次图片数量。

new-api 的任务用量表达式直接返回美元。例如 `u("seconds") * 0.4` 表示每秒四十美分，五秒为两美元；如果用量是 Token，需要在任务表达式中明确写出百万单位换算。普通 Token 表达式与任务表达式的换算规则不能混用。

## 7.4 成本、售价和预留要分列

预留可以使用保守估算，而最终售价遵守请求冻结的价格合同，上游成本则来自供应商用量和采购价格。为了限制风险多预留 20%，不意味着最终多收费 20%。同样，账单中缓存价格降低，也不意味着准入时已经能预测缓存命中。

建议每笔记录至少包含计价模型、价格版本、分组倍率、输入与输出类别、用量来源、预留金额、最终费用以及未知原因。金额计算应选用明确精度的整数或十进制定点数，统一舍入点，限制数量和乘积，拒绝负数、NaN 和溢出。

**练习：** 将上例分组倍率改为 1.5，再把 `cr` 项移除，分别算出费用。解释两次变化中，哪个改变单价规则，哪个只是乘数变化。
