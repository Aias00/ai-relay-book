# 附录 C：术语与容易混淆的边界

| 术语 | 本书中的含义 |
| --- | --- |
| 预扣 | 先实际扣减额度，完成后按差额补退 |
| 预留 | 占用可用预算，尚未改变已结算余额 |
| 准入 | 在发送上游之前决定请求是否获得预算、并发等资格 |
| 在途 | 已获资格但尚未结束相应执行或计费阶段 |
| 结算 | 将已确认消费按价格合同记入账户 |
| unknown | 执行或用量证据不完整，不能按零处理 |
| usage | 上游报告或本地估算的用量，需保留来源 |
| Quota | new-api 的内部额度单位，默认每美元五十万 |
| 微美元 | 本书实验的整数单位，每美元一百万 |
| TTFT | 首个业务 Token/内容延迟，不等同于心跳首字节 |
| fallback | 切换候选模型或账户，不自动保证安全重放 |
| 幂等 | 同一操作重复处理不重复产生其业务效果 |
| outbox | 与数据库业务变更一起提交的待发送事件记录 |
| 租约 | 有期限的处理资格，不是远端执行结束证明 |
| fencing version | 用于拒绝旧所有者晚到写入的版本标识 |
| fail-open | 辅助检查失败时允许继续，需明确承担风险 |
| fail-closed | 无法确认资格时拒绝或暂停 |
| 定价快照 | 固定本次请求采用的费率、倍率和版本 |
| 账务对账 | 将请求、用量、资金变化和供应商证据关联核对 |

Redis 原子性只覆盖脚本操作的存储范围；数据库事务只覆盖对应数据库事务内的修改；网络取消只表达本地意图。组合这些机制需要显式的状态转换和恢复合同。
