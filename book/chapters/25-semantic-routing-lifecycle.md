# 第 25 章：完整的网关语义路由流程

语义路由不仅是调用一个分类模型。它把客户端意图、能力约束、模型质量、会话连续性、缓存与负载组合成可执行决定，并为失败、计价和效果评估保留证据。本章提供可逐步落地的目标流程，不声明三个参考工程已经具备全部能力。

## 25.1 明确路由产品的契约

具体模型名通常应被尊重；只有客户端选择 auto 一类路由产品，或接口明确授权替换时，才动态选择模型。路由产品应说明允许模型、供应商范围、质量与延迟偏好、降级规则和收费方式。

统一产品售价与按实际模型收费是两种契约。不能先按便宜模型吸引请求，再在结算时无约定地按昂贵模型收费。路由也不能违反租户的数据区域和供应商限制。

## 25.2 总体链路

```text
鉴权与基础准入
    → 确认动态路由权限
    → 提取硬约束与会话状态
    → 规则或轻量语义分类
    → 筛选质量合格模型
    → 比较连续性、缓存、成本与延迟
    → 选择执行资源并完成容量与费用准入
    → 冻结路由决定与价格
    → 协议转换、执行、SSE 返回
    → 用量确认、结算与效果评估
```

请求级状态与尝试级状态分开。配置可以更新，但活动请求继续使用已确定的规则，除非触发明确的撤销或取消策略。

## 25.3 鉴权、约束与请求身份

在产生分类费用前完成身份、权限、大小校验、基础限流和过载检查。建立 request_id、租户与账户、路由产品、截止时间和策略版本。

从结构提取模态、工具调用、结构化输出、流式要求、上下文长度及显式缓存引用；从权限提取模型、供应商、区域和费用限制。这些是硬约束，评分再高也不能绕过。

客户端文本中的“忽略预算”“选择未授权模型”只是输入内容，不能变成服务器规则。分类结果也只能影响允许范围内的选择。

## 25.4 会话状态与分级分类

会话状态可包含任务类型、当前模型、优先资源、模板版本、摘要引用、最近切换原因和版本。会话标识需要租户隔离，不能用 IP 代替。

同一会话并发请求时，旧轮次晚完成不能覆盖新轮次状态。使用轮次或条件版本更新；是否串行执行由产品决定。

分类优先利用显式任务标签与请求结构。规则不确定时，使用轻量分类器读取最新消息和必要摘要，输出任务、难度、能力需求及置信度。分类超时或低置信度时使用预设保守路线，不无限升级分类模型。

“继续修第二个问题”必须结合状态判断，不能只看最新一句。分类器自报置信度也不是准确概率，应通过标注样本校准。

## 25.5 模型筛选与评分

根据任务类型和质量评估形成合格模型集合。质量依据包括任务测试、人工审阅和实际反馈；HTTP 成功率与模型名字都不能替代质量证据。

在合格集合中比较会话连续性、缓存期望、输入输出费用、排队、首内容延迟、总耗时和近期失败情况。初期使用可解释规则，不必训练复杂的评分模型。

```text
当前模型能力足够、负载合理、切换收益不明显
    → 保持
能力不足、不可用，或其他候选有明确收益
    → 切换
```

收益应覆盖缓存冷启动、上下文迁移和分类开销。没有合格候选时按约定拒绝或降级，不应为成功率静默丢失必要能力。

## 25.6 上游选择、准入与冻结

模型确定后选择供应商、部署和账号。缓存亲和只是偏好，必须服从权限、健康、停用与容量。占用并发槽位或资金预留失败时，允许有限重选，并受总截止时间约束。

最终执行前保存路由决定：对外产品、实际模型与资源、选择原因、策略版本、价格快照、允许的重试范围。上游价格与客户售价分开保存或引用。

按实际模型收费时，选择结果需满足客户约定的费用限制。若重试可能更换模型，必须提前规定客户收费规则与成本承担；不能通过改变 attempt_id 绕过用户费用上限。

能力与长度校验可以在初筛使用保守估算，最终转换、模板插入后再检查实际请求，避免候选模型看似可用却在发送时超限。

## 25.7 执行与流式一致性

稳定构造上下文，转换协议，取得有效凭证并记录 attempt_id 后调用上游。路由解释与随机追踪标识不必插入提示词。

SSE 一旦向客户端输出，不把另一模型的新生成直接拼接进来。处理有界缓冲、背压、空闲超时和取消，不能按网络块数量计 token。输出前重试也要考虑上游可能已执行；工具或其他副作用需要额外幂等约束。

普通断流不等于可恢复会话。续传需要第 21 章所述的事件存储与独立生成生命周期。自动升级强模型再试，也不具备天然安全重放保证。

## 25.8 结束、结算与反馈

执行结果记录成功、取消、超时、重试和实际模型。费用与性能记录路由器开销、摘要、排队、首内容、缓存读写和最终用量。质量记录格式校验、工具结果、用户反馈或独立评估。

用量可靠交接，按冻结价格幂等结算。缺失或估算用量标记来源和完整性。用户继续追问不一定表示上一轮失败，不能把单一行为直接作为质量标签。

## 25.9 策略上线与回滚

按离线样本、影子决定、小流量灰度、扩大或回滚推进。只生成影子路由决定而不执行候选模型，只能验证选择分布和规则覆盖，不能证明答案质量。真实对照调用增加成本与数据处理范围，需要明确授权和预算。

验收以质量达标后的每个成功任务总成本与延迟为核心，包括分类、摘要、缓存写入、失败尝试和重试费用。不要只优化小模型占比或缓存命中率。

第一版可只覆盖少量任务和候选模型，采用规则优先、会话软亲和、固定切换门槛、明确回退与完整路由日志。接口可以保持进程内实现；只有容量、复用或权限隔离要求明确时再拆服务。

## 25.10 设计验收练习

构造一个长文档多轮问答：首轮通用问答，第二轮复杂代码分析，第三轮要求总结。分别解释为什么保持或切换模型、哪些前缀可能复用、价格何时冻结，以及分类超时和上游 429 时如何回退。

再让两个请求同时更新同一会话，并让其中一个节点在用量上报后、收到确认前崩溃。合格答案应说明会话版本冲突、幂等事件、价格版本和缓存作用域，不能只回答“放进 Redis”。
